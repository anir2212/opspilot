# Backup job failed

## Signal and scope
This runbook applies to the local `backups` demo service. Symptoms: Backup status failed and error code recorded. Record the alert start time, affected requests, current release, and related services before suggesting a cause. Treat this document as guidance, not authorization to change a live system.

## Investigation
Likely cause to test: Client offline, repository unreachable, authentication or policy error. Read backup job error code and policy; verify client and destination reachability; rerun only after cause is fixed; preserve the previous valid restore point. Link each observation to its Prometheus query, trace, backup job, or incident number. Compare the signal against a healthy interval; a coincident deploy alone does not prove causation.

## Recovery and verification
Any state-changing step requires a human-approved change request. A retry succeeds and restore-point age is within policy. Record the exact time, owner, and evidence after verification. If the expected recovery does not occur, reopen the hypothesis and escalate.
