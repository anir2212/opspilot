# Processor authentication

## Signal and scope
This runbook applies to the local `payments` demo service. Symptoms: Processor responds unauthorized. Record the alert start time, affected requests, current release, and related services before suggesting a cause. Treat this document as guidance, not authorization to change a live system.

## Investigation
Likely cause to test: Expired credential or wrong secret scope. Confirm error code without logging secret values; check rotation timeline and secret reference; coordinate credential fix with owner. Link each observation to its Prometheus query, trace, backup job, or incident number. Compare the signal against a healthy interval; a coincident deploy alone does not prove causation.

## Recovery and verification
Any state-changing step requires a human-approved change request. Authorized synthetic transaction passes and no secrets appear in logs. Record the exact time, owner, and evidence after verification. If the expected recovery does not occur, reopen the hypothesis and escalate.
