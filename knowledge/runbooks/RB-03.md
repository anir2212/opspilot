# Gateway memory growth

## Signal and scope
This runbook applies to the local `gateway` demo service. Symptoms: RSS rises steadily and process restarts. Record the alert start time, affected requests, current release, and related services before suggesting a cause. Treat this document as guidance, not authorization to change a live system.

## Investigation
Likely cause to test: Unbounded cache or retained request objects. Inspect resident memory slope and restart count; compare release versions; capture heap profile in a safe replica; draft rollback if growth began after deployment. Link each observation to its Prometheus query, trace, backup job, or incident number. Compare the signal against a healthy interval; a coincident deploy alone does not prove causation.

## Recovery and verification
Any state-changing step requires a human-approved change request. Memory stabilizes across two traffic cycles. Record the exact time, owner, and evidence after verification. If the expected recovery does not occur, reopen the hypothesis and escalate.
