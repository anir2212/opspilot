# Backup restore test

## Signal and scope
This runbook applies to the local `backups` demo service. Symptoms: Backup job succeeds but recovery confidence is unknown. Record the alert start time, affected requests, current release, and related services before suggesting a cause. Treat this document as guidance, not authorization to change a live system.

## Investigation
Likely cause to test: Restore path has not been exercised. Select non-production restore target; verify checksum and application readability; record recovery duration. Link each observation to its Prometheus query, trace, backup job, or incident number. Compare the signal against a healthy interval; a coincident deploy alone does not prove causation.

## Recovery and verification
Any state-changing step requires a human-approved change request. Restored data passes integrity check. Record the exact time, owner, and evidence after verification. If the expected recovery does not occur, reopen the hypothesis and escalate.
