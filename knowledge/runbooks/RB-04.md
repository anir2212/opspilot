# Gateway CPU saturation

## Signal and scope
This runbook applies to the local `gateway` demo service. Symptoms: CPU above ninety percent and rising queue depth. Record the alert start time, affected requests, current release, and related services before suggesting a cause. Treat this document as guidance, not authorization to change a live system.

## Investigation
Likely cause to test: Compute-heavy path or excessive retries. Correlate CPU with request rate; inspect profiles and retry volume; disable optional batch work only with approval; consider capacity planning. Link each observation to its Prometheus query, trace, backup job, or incident number. Compare the signal against a healthy interval; a coincident deploy alone does not prove causation.

## Recovery and verification
Any state-changing step requires a human-approved change request. CPU and queue depth return to normal. Record the exact time, owner, and evidence after verification. If the expected recovery does not occur, reopen the hypothesis and escalate.
