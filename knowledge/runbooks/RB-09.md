# Payment timeout budget

## Signal and scope
This runbook applies to the local `payments` demo service. Symptoms: Payment calls exceed timeout and gateway latency rises. Record the alert start time, affected requests, current release, and related services before suggesting a cause. Treat this document as guidance, not authorization to change a live system.

## Investigation
Likely cause to test: Processor latency exceeds client timeout budget. Compare upstream and gateway spans; check connection timeout and retry count; capture processor status; propose timeout change with load test evidence. Link each observation to its Prometheus query, trace, backup job, or incident number. Compare the signal against a healthy interval; a coincident deploy alone does not prove causation.

## Recovery and verification
Any state-changing step requires a human-approved change request. End-to-end p95 and success rate recover. Record the exact time, owner, and evidence after verification. If the expected recovery does not occur, reopen the hypothesis and escalate.
